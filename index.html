Protocol & setup notes for debugging

This page expects the updated Hall debugger firmware. The legacy text characteristic still sends R:120.5 for compatibility; the new diagnostic characteristic sends a fixed 20-byte binary packet, and the config characteristic supports calibration writes.

BLE UUIDs

Service: 12345678-1234-5678-1234-56789abcdef0
Legacy RPM text: 12345678-1234-5678-1234-56789abcdef1
Diagnostic notifications: 12345678-1234-5678-1234-56789abcdef2
Config read/write: 12345678-1234-5678-1234-56789abcdef3

Binary telemetry packet (little-endian)

Byte 0 protocol version; byte 1 flags; bytes 2–3 sequence; bytes 4–7 accepted edges; bytes 8–11 interval in microseconds; bytes 12–13 RPM × 10; bytes 14–15 age since last accepted edge in milliseconds; bytes 16–17 rejected-edge count (saturates at 65,535); bytes 18–19 device-calculated speed × 100 km/h.

Flags: bit 0 interval valid; bit 1 stopped/stale; bit 2 suspicious interval; bit 3 input currently active; bit 4 hardware capture; bit 5 baseline established.

Calibration packet

12 bytes: version, command (0 apply / 1 reset counters), magnets per revolution, reserved byte, circumference in mm (u16), minimum interval in microseconds (u32), stop timeout in milliseconds (u16). Firmware validates all ranges before applying them.

Electrical notes

DRV5033 is an open-drain output: it needs a pull-up to 3.3 V unless your breakout already provides one. Firmware configures no internal pull. For the active-low setting, physical LOW means active. The 30 kHz sensor bandwidth is not the same as the wheel's pulse rate; wheel edges at riding speeds are only tens of events per second.
